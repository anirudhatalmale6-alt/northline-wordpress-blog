Every system I have built for myself has gone through the same arc: enthusiastic construction, elaborate structure, quiet abandonment. The one that finally stuck is the one I built while assuming the enthusiasm would run out — because it always does, and a system that only works while you are excited about it is not a system.

Design for the bored version of yourself

The version of me who sets up a note system has an hour, a coffee and a strong opinion about taxonomy. The version who has to use it is tired, in a hurry and does not care. Every design decision should serve the second one, and almost every appealing design decision serves the first.

Tag hierarchies, linked databases, templated front-matter — these are all enjoyable to build and all impose a small tax at exactly the moment you have the least patience to pay it. The tax is what kills the habit, and it is invisible during setup.

What survived

  • Markdown files in one folder. Not a tree. One folder, thousands of files, sorted by name. Directories are a decision at write time; search is a decision at read time, and read time is when I actually know what I want.
  • Dates in the filename. 2026-03-14-something.md. Sorts chronologically for free, and the date is visible in every listing without opening anything.
  • No front-matter. I tried YAML headers for two years. I never once queried them.
  • Git, committed hourly by a cron job. Not for collaboration — for the ability to see what I thought last March without having been disciplined about it.

Structure imposed at write time is a bet that you know now what you will want later. You do not, and the bet is expensive because you place it every single time you write.

The one piece of structure I kept

A single index file, hand-maintained, listing the fifteen or so notes I actually return to. Not generated — written by hand, which is why it stays short and why it is useful. A generated index of everything is just the folder listing again.

The index is also the only place I allow myself to be tidy. Everything else can be a mess, because search does not care about mess and I no longer pretend that browsing is how I find things.

On formats that outlive tools

The reason for plain text is not purity. It is that I have now watched four note applications either shut down, get acquired and degrade, or change their export format in a way that lost data. The files I wrote in 2011 still open. That is the entire argument and it has never needed a better one.

Use whatever editor you like on top — I change editors roughly annually and it costs nothing, because the editor is not where the notes live. That separation is the only architectural decision in the whole stack, and it is the one doing all the work.
